# V0.9 市场健康仪表盘记录

## 需求与决定

用户确认总览看板采用两行、每行五卡的市场健康仪表盘：第一行五灯使用显眼的圆形指示灯；第二行分别以迷你走势、双线、比例条和半圆指针展示 10Y–2Y、等权表现、Put/Call、恐慌贪婪，最后一格预留。仪表盘有自己的“重新计算”按钮，只在点击时更新。保存最后一次数据，局部失败保留旧值和原日期。五灯口径参考旧周报，界面设计见[设计文档](superpowers/specs/2026-10-26-v09-market-health.md)。

用户口头称“CNBC 恐慌贪婪”，核对后使用实际发布该股市指标的 **CNN Business Fear & Greed**，页面和来源都明确写 CNN；不把 CNN 值称为 CNBC。人工五灯判断和文字继续保留为独立备注，自动颜色不会被人工颜色覆盖。

## 当前交付

- 新增 `/api/market-health` 按需服务端接口，FRED、CNN 和已连接的 Longbridge 并行获取；单源失败不会清空其他卡。Longbridge 令牌继续只在服务端会话中，浏览器仅保存公开指标和人工备注。
- VIX 使用旧周报 <20 / 20–30 / >30 的灯色；高收益债 OAS 使用 <4 / 4–5 / >5，并对四周扩大超过 100bp 标红。杠杆用芝加哥联储周度 NFCI 杠杆子指数过去 52 周分位，**70% / 90% 为本项目参考阈值，并非旧周报原阈值**。
- 拥挤度用 SPY 期权 Put/Call 量比过去约 260 个交易日的分位；这是代理指标，不冒充 CFTC 头寸或综合拥挤度。第二行的 Put/Call 同样明确为 SPY；等权对比用 RSP/SPY 两只 ETF 同日起点归一化。
- 桌面五列两行布局，窄屏重排。数值、解释、来源、原始发布日期和“旧数据”状态均直接在卡上。CNN 指标为发布值，指针显示 0–100 位置。

## 数据限制与后续修复

- **市场宽度仍待完整数据**：Longbridge 当前 `constituent` 对 `.SPX.US` 报告总数 501，但实际只返回 20 个项目；无法据此算所有标普 500 成分股位于 MA50/MA200 上方的比例。卡片保持灰灯并说明原因，不把当日上涨家数误称均线宽度。补全后按旧周报 >60%、40–60%、<40% 规则计算。
- VIX 期限结构、CFTC 头寸、FINRA 月度保证金债务尚未接入；当前对应卡用已标注的单一代理指标或只按 VIX 现值评分。五灯不等权，不能将单灯颜色当成买卖信号。
- FRED OAS 与 10Y–2Y 是日度，NFCI 杠杆是周度。显示实际发布日期，不称实时数据。CNN 页面使用的 JSON 端点未提供稳定公开 API；若其结构或访问策略改变，保留旧值并显示失败原因。
- 本地预览端口 3101 为独立 V0.9 工作分支；原端口 3100 仍显示上一版。3101 的 Longbridge 授权需单独连接，测试时未使用用户凭据，所以长桥卡显示待连接。
- 尚未发生 V0.9 上线后用户报告的 bug；后续修复请追加本节并同步 PR 描述。

## 验证

- 纯函数测试覆盖 VIX/OAS 阈值、分位、错误时保留旧值；数据解析测试覆盖 FRED、CNN、SPY 期权量及 RSP/SPY 对齐；组件测试覆盖十格、按需更新、本地保存、失败旧值。
- `pnpm lint` 和 `pnpm build` 通过；构建包含 `/api/market-health`。最终全量测试以 `pnpm exec vitest run --maxWorkers=2` 运行：33 个文件、130 项测试全部通过。第一次使用默认较高并发时两个旧模块出现超时/时序失败，较少并发的最终全量运行均通过。
- 本地浏览器在 1250px 宽度看到五列第一行与五列第二行，FRED OAS、NFCI 杠杆、10Y–2Y 和 CNN 发布值能够填入真实卡片；无需 Longbridge 的卡正常更新，需 Longbridge 的卡明确显示待连接。刷新只调用仪表盘接口，资产卡未被更新。
