# V0.6 市场动态设计（待确认）

## 意图

在 Enterprise AWE Trading Terminal 的左侧导航加入“市场动态”。使用者主动点击“更新”，在几十秒内浏览过去数天可能影响全球市场的新闻，快速判断发生了什么，并能打开原文核对。不做持续推送或自动轮询。

## 已确认的需求

- 时间窗口可选过去 3、5、7 天，建议默认 3 天。
- 顶部展示跨栏目焦点，下面分栏浏览：地缘与全球风险、宏观与政策、AI 与科技、其他产业与公司。产业领袖发言、访谈、产品发布归入相应产业栏；重要财报结果和企业动作归入公司栏。
- 每栏先显示约 6–8 条，可展开浏览最多约 20 条。新闻质量不足时不凑满。
- 新闻卡显示标题、简短事实摘要（来源允许且有足够信息时）、来源、发布时间与原文链接。点击原文离开本站阅读；不在本站复制付费正文。
- 来源范围扩大到长桥与全球新闻索引，并重点覆盖新浪财经、Bloomberg、The Wall Street Journal、Reuters。**重要性优先排序**：指定媒体仅在同一事件的多篇报道质量相近时优先，不固定占比，也不压过更重要的其他来源报道。
- 刷新失败保留上次结果，显示最近成功更新时间和未成功的来源；已显示新闻不会因页面切换而消失。

## 方案比较与选择

1. **仅用长桥新闻检索**：接入快，现有 MCP 已连接；抽样发现检索结果混有泛投资文章，全球事件覆盖与栏目质量难以保证。
2. **长桥 + GDELT 新闻索引，统一筛选**：推荐方案。长桥补充金融与公司新闻；GDELT 扩大跨地区、跨语言的新闻发现范围，并可按发布时间和来源域名检索。需要服务端筛选、去重和失败隔离；开发前须抽样验证目标媒体覆盖率及响应时间。[GDELT DOC API 说明](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/)。
3. **逐家购买媒体内容服务**：可以获得更完整、稳定的授权内容，但增加订阅、接入和使用限制。Bloomberg 与 Reuters 都提供正式内容授权渠道；V0.6 暂不依赖它们。[Bloomberg Media Distribution](https://www.bloomberg.com/distribution)、[Reuters 授权](https://reutersagency.com/license-reuters-content/)。

采用方案 2 作为设计方向。用户已同意整体版式和按重要性排序；本文仍待确认，之后再开始产品代码实施。

## 数据处理与可信度

- 请求从 Next.js 服务端发起；现有 Longbridge 凭据仅保留服务端。浏览器只接收可公开显示的新闻元数据与摘要。
- 对候选文章先按用户指定时间窗口和主题过滤，规范化原始来源，移除重复链接及同一事件的重复标题，再按事件对市场的潜在影响、报道具体程度、来源可核验性和新近程度排序。前端明确标为“精选新闻”，不宣称客观穷尽全球最重要事件。
- 同一事件有多篇报道时，保留信息较完整且可追溯的报道；新浪财经、Bloomberg、WSJ、Reuters 是优选来源，但不是强制置顶。不同来源的关键事实矛盾时不合成确定结论。
- 只有获取到许可范围内的可靠摘录或足够事实时才写简述；否则只展示标题、来源与原文链接。不用标题臆造细节，不绕过付费墙，不复制全文。某些 Bloomberg / WSJ 报道打开后可能需要读者自己的订阅。
- 新闻检索可能漏报、误分类或延迟。每条保留来源和发布时间；部分来源失败时显示已获取内容并提示缺口。限制并行请求数量和单次等待时间，以便满足手动更新的速度目标；实际耗时以接入实测为准。

## 界面与状态

- 页面顶部：标题“市场动态”、3/5/7 天选择、“更新”按钮、上次更新时刻和来源状态。焦点区域显示约 5 条跨栏目重点新闻。
- 下方四栏卡片：标题、最多两句摘要、来源、发布时间、原文入口。默认每栏 6–8 条，按“显示更多”扩展，最多约 20 条；栏目为空时说明该窗口内没有足够可信的结果。
- 浏览器保存最近一次成功的公开新闻快照；换页返回或刷新后仍可阅读，手动更新成功才替换，失败不清空。
- 新闻只用于信息速览；财经日历继续负责未来事件日期，两页可在导航中互相进入。

## 验收与开放问题

- 四个现有页面可进入“市场动态”；刷新时能得到规定时间窗口内的新闻，分类、去重和原文链接可检查。
- 重要性排序生效；指定媒体不抢占所有焦点位。来源缺失、部分失败、完全失败和缓存恢复均有明确状态。
- 开发前抽样验证 GDELT 与长桥的目标媒体覆盖率、接口可用性、每栏合格条数和响应时间。若某媒体索引不稳定，界面不承诺固定出现该媒体内容。
- 尚待用户确认：这一版采用“简报卡 + 原文链接”，不制作站内长篇文章详情。
