# V1.15 温度六页重建：确认方案

用户要求保留指标大全与资产风向，删除旧市场温度、估值分析、短线精灵，依据最新施工图重建六页：动能分析、估值分位、A股雷达、美股雷达、港股全景、亚太温度，作为金丝雀二级入口。用户已同意将“空仓检验/仓位规则”改为状态检验和观察条件。

基线：docs/temperature-suite-requirements.md。功能、算法、数据范围与规则模板以施工图及提供的参考实现为准，蓝白主题与现站一致。八只动能、七只有效估值加道指不可得、六组市场模块按完整范围实现。位置/动能共用算法；分档、代理、PE口径、基准日期对齐不能简化。

实施路径采用现有React页面外壳+六页共享隔离文档，复用经核对的参考计算和渲染，图表库本地部署。替代方案是将参考网站整个嵌入，或从零重写全部算法：前者会混入不相关模块及数据，后者会增加口径漂移；因此采用局部移植且与本网站接口/持久目录整合。不依赖8765服务，不新增顶级“温度”分组。

明确适配：六页独立锁、独立刷新、持久结果读盘，F5和服务重启不回退；港股n=0视为降级；legacy拥挤保留并标注；错误与耗时字段类型固定。实时板块单独时间戳，陈旧读数显著提示；不将各种0–100分数混成同一总分。

先保留提供文件的公开历史序列与两个不可重建归档（恐惧贪婪/沽空），明示导入时间和原观测日；再逐页真实更新核验。所有运行数据存于本机源码之外，更新先在临时目录生成，再验证与原子发布；失败保留原结果和归档。所有来源与缺项必须可见，不以静态示例冒充新抓取。

验收必须覆盖六页完整内容、独立刷新、同页429、跨页不互斥、失败恢复、刷新后重载同值、移动端容器滚动、图表切换及统计/口径一致性。

实现中明确的口径细节：合成分数与经验历史分位分别展示，历史排名从完整结果序列计算；亚太曲线按各自交易日展示，基准不足时不外推；缺失核心广度直接拒绝更新。陈旧提示采用四个自然日启发式并展示来源日期，不标成精确交易日判断。公开源限频优先保证样本完整，实际刷新可能超过施工图理想时间预算，实测记录见版本交付文档。
