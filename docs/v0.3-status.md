# V0.3 需求、交付与修复记录

需求来自用户在对话中提供的 full satellite 持仓地图示意图；原始图片未存入公开仓库。详细设计：[V0.3 需求文档](superpowers/specs/2026-10-24-v03-portfolio-matrix.md)。实现提交及讨论：[GitHub PR #5](https://github.com/u17kill/Enterprise-AWE-Trading-terminal/pull/5)。

## 确定的需求

- 按截图使用横向“进攻 / 均衡 / 防御 → 14 个主题”、纵向“美国 / 中国 / 日韩台印 / 欧洲”的矩阵，而非旧版一次只看一个通道的卡片页。
- 把图中的标的、名称与数字备注录入为初始内容。每个标的卡片、策略、主题和地区可以新增、编辑、删除。
- 灰色代表已持仓，黄色代表暂未持仓的观察标的，绿色代表计划加仓。截图中的蓝色 `put` 标注保留为文字备注，归入黄色观察状态。
- 地区行高度由该地区内容最多的单元格决定；增减卡片时自动伸缩，不在地区之间预留固定大片空白。
- 浏览器本地保存修改，并提供备份；旧版私人持仓不能在升级时被覆盖。

## 已交付

- 新矩阵录入了截图的三组策略、14 个主题、四个地区和标的备注；AI 基建与 AI 应用可并排显示两列卡片。窄屏可横向滚动。
- 点击策略、主题、地区或标的即可编辑。可添加和删除这些元素；删除包含标的的分组前会要求确认。
- 每个标的可修改代码/简称、公司或资产名称、仓位备注、状态、主题和地区。
- V0.3 使用独立的浏览器存储键。支持 V0.3 JSON 导入和导出；若浏览器中有 V1.3 数据，可下载其备份。旧键和本机 `.local/` 历史数据没有修改。
- 备份导入会检查结构与所有引用；如果任何记录会被丢弃，则拒绝替换当前地图。浏览器存储不可用时会显示“保存失败”。

## 数据边界与验证

- 初始标的和金额备注已写入公开仓库，可被任何人查看；原始截图未入库。这些条目只是用户提供的可编辑示意数据，不代表已核验的当前持仓、股数、市价或盈亏；用户之后在浏览器里修改的内容只保存在本地。
- 改版时全套 73 项测试、ESLint 和生产构建通过。行高修复后，持仓地图组件 5 项测试及生产构建再次通过；尚未通过自动化浏览器取得视觉截图。
- PR #5 是草稿，目标分支为 V1.3 PR #4 的分支；合并顺序仍取决于上游 PR。
- 2026-11-03 修复随 V1.5 草稿 PR #22 提交。本机共享持仓文件默认放在用户的 `Documents/Codex/.awe-terminal-data/portfolio-matrix.json`，不属于 Git 仓库；接口只允许本地地址和同源请求。旧端口中的浏览器副本受浏览器隔离，若它比当前端口副本更新，需在旧端口导出并在新页面导入；系统不会猜测哪个未带时间戳的旧副本更新。
- 本轮持仓相关回归测试 **8/8**、TypeScript、全仓 ESLint 和隔离的 Next.js 生产构建通过。未把 V1.5 整版或全仓历史测试宣称为已验收。
- 3102 切换至修复版后，先从 in-app 浏览器读入初始 75 项；随后在 Chrome 同源浏览器发现一个与初始内容有 4 项差异的旧副本。先保存两份本机备份，再将 Chrome 副本经本地接口恢复；服务端文件与旧副本的 75 项逐项比对一致。未读取离线 3101 的浏览器存储，因此不能断言它是否另有更新版本。
